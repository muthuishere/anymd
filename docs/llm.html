LLM features

Image captioning, scanned-PDF reading and audio transcription. All of it is opt-in, and supplying it is the only thing that makes a conversion touch the network.

The shape

Two fields on Options, both interfaces, both nil by default:

type Describer interface {
	Describe(ctx context.Context, img []byte, mime, hint string) (string, error)
}

type Transcriber interface {
	Transcribe(ctx context.Context, audio []byte, mime string) (string, error)
}

This is markitdown's llm_client= parameter, expressed as an interface rather than a concrete SDK object. Anything that can look at bytes and return text satisfies it: a hosted API, a local model, or a stub in your tests.

With both nil — the zero Options, and what you get if you never think about this page — anymd makes no network calls of any kind during conversion. That guarantee is what lets you point it at untrusted documents. Supplying a Describer is opt-in, per-conversion, and visible in the caller's code.

Side by side with markitdown

The Python you probably arrived with:

# markitdown
md = MarkItDown(llm_client=OpenAI(), llm_model="gpt-4o")
md.convert("document_with_images.pdf")

The Go equivalent:

// anymd
d := llm.New(llm.Config{Model: "gpt-4o"})
res, err := anymd.Default().ConvertFile("document_with_images.pdf",
	&anymd.Options{Describer: d})

And from the shell, where the config file supplies the model and the environment supplies the key:

anymd --llm document_with_images.pdf

The CLI page has the full flag list. The short version:

FlagEffect
--llmEnable image captioning. One model call per image.
--llm-config FILEConfig file; default ~/.config/anymd/anymdconfig.json.
--llm-model NAMEOverride the vision model from the config file.
--llm-base-url URLOverride the endpoint. A local Ollama or vLLM works.

--llm-transcribeAlso transcribe audio. A separate endpoint and a separate charge.

Every one of those except --llm itself is a usage error without --llm. A flag that silently did nothing — --llm-model above all, whose absence looks like the model was applied — is worse than a refusal.

What it unlocks

Scanned PDFs, without rasterization

A scanned PDF has no text layer at all: every page is one large embedded image XObject. anymd cannot rasterize a page — there is no pure-Go PDF renderer, and a cgo one (pdfium, MuPDF) would break the package's central promise.

It does not have to. The pixels the scanner produced are already sitting in the file as a JPEG, so the image is lifted straight out of the object graph and handed to your Describer. No rendering step, no native dependency, and the constraint that looked fatal turns out not to bind.

Filters keep this honest. An image under 4096 bytes, or under 64 pixels on a side, is a logo, a rule or a signature stamp rather than a page scan, and is skipped. With no Describer, not a byte of this code runs and a text-free PDF still returns ErrNoTextLayer exactly as before.

Embedded images in docx and pptx

Word and PowerPoint reference their pictures through relationship ids. Without a Describer, anymd emits the placeholder and whatever alt text the author wrote — that is all a pure-Go parse can honestly say. With one, the media part is read and captioned, and the author's own alt text is passed to the model as the hint:

text += "\n\nThe document labels this image: " + hint

The author already told you what the picture is. Discarding that and asking a model to guess from scratch is strictly worse.

Vector parts (EMF, WMF, SVG) are excluded: no hosted vision model accepts them, so sending one is a wasted call.

Standalone images

An .jpg or .png normally converts to its pixel dimensions and EXIF metadata. With a Describer, a caption is added. Without one, the pixels are never described.

Audio

The audio converter is inert until you supply a Transcriber: its Accepts returns false when Options.Transcriber is nil. That is deliberate. An accepted .mp3 with nothing to read it would replace an honest "unsupported" error with an empty document.

Unlike a caption, a failed transcription is a hard error, because the transcript is the file's entire content. An empty transcript is a failure, not a successful conversion of silence.

The llm package

github.com/muthuishere/anymd/llm is the ready-made implementation of both interfaces. Vision goes through toolnexus, which handles API keys, retries, backoff and the OpenAI-vs-Anthropic wire difference; this package is the vision message and the glue.

func New(cfg Config) *Client
func FromConfigFile(path string) (*Client, error)
func FromClient(c *tn.Client, prompt string) *Client
func NewTranscriber(cfg Config, model string) *Transcriber
func TranscriberFromConfigFile(path, model string) (*Transcriber, error)
func Load(path string) (Config, error)
func ConfigPath() (string, error)

The one-liner for the common case reads the config file and returns a ready Describer. A missing file is not an error — you get a client configured purely from the environment:

d, err := llm.FromConfigFile("") // "" = the default location
if err != nil {
	log.Fatal(err)
}
res, err := anymd.Default().ConvertFile("deck.pptx", &anymd.Options{Describer: d})

Both at once:

cfg, err := llm.Load("")
if err != nil {
	log.Fatal(err)
}
opts := &anymd.Options{
	Describer:   llm.New(cfg),
	Transcriber: llm.NewTranscriber(cfg, ""), // "" = whisper-1
	LLMTimeout:  30 * time.Second,
}

FromClient is the escape hatch: wrap a toolnexus client you built yourself — a bespoke transport, a shared client across your app, metrics hooks — and anymd adds nothing to your configuration except the vision message.

The wire format is OpenAI-compatible, so OpenRouter, Ollama, vLLM, LM Studio and Azure all work by setting base_url. Nothing else needs to change.

The config file

Machine-specific settings live outside the repo, at ~/.config/anymd/anymdconfig.json. That path is $XDG_CONFIG_HOME/anymd/ when set, otherwise ~/.config/anymd/, on every platform including macOS: this deliberately does not use os.UserConfigDir(), which resolves to ~/Library/Application Support there. A CLI's config belongs where a developer expects to find and edit it.

{
  "model":    "openai/gpt-4o-mini",
  "base_url": "https://openrouter.ai/api/v1",
  "api_key":  "${LLM_API_KEY}",

  "proxy":    "${HTTPS_PROXY}",
  "headers":  { "HTTP-Referer": "${SITE_URL}" },

  "retries":    2,
  "timeout_ms": 60000,
  "anthropic":  false,
  "insecure_skip_verify": false
}

anymd config init writes a starter file at mode 0600 and never overwrites; anymd config path prints the location; anymd config show prints the resolved config with every secret redacted.

${VAR} interpolation, and why an unset one is fatal

Every string field supports ${VAR} interpolation from the environment. That is how a key stays out of the file.

An unset or empty variable is an error, not an empty string. Silently expanding a missing key to "" would send an unauthenticated request and surface as a confusing 401 from the provider, three layers away from the cause. The error names the field and the variable:

llm: api_key references unset environment variable(s): LLM_API_KEY (in /home/you/.config/anymd/anymdconfig.json)

Errors name the variable, never its value. Nothing in this package prints an API key, not even masked — not in an error, not in config show, not in a failed-request body, which is truncated and never echoes the Authorization header.

insecure_skip_verify disables TLS verification for a self-signed corporate proxy. It makes the connection interceptable; do not point it at the public internet.

Cost and privacy

Two things are true at once and both matter.

It costs money, per call. One model call per captioned image. One per transcribed file. A deck with 40 distinct figures is 40 calls. Transcription is billed on a different endpoint from captioning, which is why --llm-transcribe is a separate flag rather than being bundled into --llm — bundling would charge people for something they did not ask for.

It sends document content to a third party. --llm uploads the images out of your document (and, on a scanned PDF, the page itself) to whatever endpoint base_url names. If that is not acceptable for a given document, do not pass the flag — and note that the default, with no flag, sends nothing anywhere. Pointing base_url at a local Ollama or vLLM keeps the bytes on your machine.

The built-in guards

GuardValueWhy
sha256 dedupper documentThe same logo on 60 slides is one call, not 60. Failures are cached too, so a refused image is not retried 59 times. Deduplicated repeats do not count against the cap — they cost nothing.
Size floor4 KiBBelow that an embedded image is furniture: a spacer, a bullet glyph, a rule, a 1×1 tracking pixel. Comfortably below any real photograph, comfortably above the decorative PNGs Office scatters through a template.
Captions per document50A 300-slide deck must not silently fire 300 requests. Past the cap, every further image degrades to its alt text, exactly as if no Describer had been supplied.
Scanned pages per PDF20A 500-page scan must not turn one Convert into 500 requests. Past the cap anymd stops and says so in the output.
Per-call timeout60sOptions.LLMTimeout. A slow model must not stall a whole document.
Audio upload limit25 MiBThe documented limit of the hosted endpoint. Refusing above it turns a slow upload ending in a 413 into an immediate, readable error.

A Describer failure is not an error for the document. A model outage or a rate limit costs you the caption; the placeholder, dimensions and EXIF are still correct, and the rest of the text still converts.

Caching conversions on disk also caches the captions, so a re-run of the same document costs nothing. See Cache.

The transcription trap

NewTranscriber posts a multipart upload to <base_url>/audio/transcriptions. OpenRouter does not implement that endpoint. If your config file points base_url at OpenRouter — which the example config does, because it is a good default for vision — transcription will fail against it. Point --llm-base-url at a server that does implement it: the hosted OpenAI API, a local whisper.cpp server, faster-whisper, or LM Studio.

anymd --llm --llm-transcribe \
      --llm-base-url http://127.0.0.1:8080/v1 \
      interview.mp3

The default when BaseURL is empty is https://api.openai.com/v1, precisely because there is no sensible aggregator default for an OpenAI-shaped endpoint. A local endpoint (localhost, 127.0.0.1, ::1, 0.0.0.0) is allowed through with no API key, since a local whisper server needs no credential; anything remote must be authenticated deliberately, and returns ErrNoAPIKey otherwise.

Transcription deliberately does not go through toolnexus. toolnexus drives chat completions — a JSON body of messages — and transcription is a multipart upload of a raw audio file. Forcing it through the chat client would mean base64-ing audio into a message the endpoint does not accept. It is plain net/http plus mime/multipart from the standard library, and adds no dependency.

The default speech model is whisper-1: every OpenAI-compatible server that implements /audio/transcriptions answers to that name. It is a constructor argument rather than a Config field because Config.Model carries the vision model, and reusing it would send gpt-4o-mini to a transcription endpoint.

Bringing your own model

You do not need the llm package. Any function satisfies the interface:

d := anymd.DescriberFunc(func(ctx context.Context, img []byte, mime, hint string) (string, error) {
	// call your own model, your own gateway, or return a canned string in a test
	return "a bar chart of quarterly revenue", nil
})

res, err := anymd.Default().ConvertFile("deck.pptx", &anymd.Options{Describer: d})
if err != nil {
	log.Fatal(err)
}
fmt.Println(res.Markdown)

Implementations must respect ctx, must not panic, and should return an error rather than a partial description when the request fails.
