# 0003 — Measure output quality against docling's ground truth

Status: **Accepted** · 2026-09-02

## Context

`bench/README.md` ended, from the first release until this record, with a
sentence admitting the hole in it:

> Output *quality* is not benchmarked here — byte counts are not fidelity.

Everything the project measured was speed, and every published claim was a speed
claim: 30× on docx, 22× on pdf, 46× on the CLI. Those numbers are real. They are
also the easy half of the problem, and optimising against them exclusively has a
predictable failure mode — a converter that returns the wrong markdown very
quickly scores perfectly on every metric the repository had.

[0002](0002-vendor-the-pdf-parser.md) is the evidence that this was not
hypothetical. It made a change to the PDF hot path and defended correctness with
"verified byte-identical output on all seven corpus PDFs" — seven files,
compared to themselves. That is a regression check, not a fidelity measurement.
It could confirm the change broke nothing; it could not have told us whether
what it preserved was any good. The lesson recorded at the end of 0002 was that
a benchmark's *explanation* needs checking as carefully as its number. This
record is the other half: a benchmark needs to measure the thing the project is
actually for.

The obstacle is that document conversion has no cheap ground truth. Hand-writing
expected markdown for a corpus large enough to be diagnostic is weeks of work,
and the result is unavoidably shaped by our own conventions — we would be
grading ourselves against our own taste. The options considered:

1. **Hand-curate a corpus.** Neutral and authoritative, and the only option that
   can call docling wrong. Too slow to start with, and a corpus small enough to
   hand-build is too small to localise a bug.
2. **Differential testing against markitdown.** No ground truth needed, and the
   corpus is already in `bench/run.sh`. But a disagreement is unattributed: it
   says the two tools differ, never which one is right, and adjudicating each
   one by hand is the work of option 1 without the reusable artefact.
3. **LLM-as-judge.** Scales, and needs no reference. It also makes the score
   non-deterministic, unauditable, and dependent on a network call — which for a
   project whose first ADR is "no network the caller did not ask for" is a poor
   thing to bolt onto its own benchmark.
4. **Borrow docling's ground truth.**

docling ships ~150 documents as (source, expected markdown) pairs under
`tests/data/<format>/{sources,groundtruth}`, 130 of them in formats anymd
claims. Two properties decide it. The pairs are machine-matchable, so the corpus
costs a path argument rather than a labelling effort. And the files are named
for the feature they exercise — `docx_lists.docx`, `textbox.docx`,
`xlsx_07_gap_tolerance_.xlsx` — so a low score arrives already localised to a
feature, which is the property option 2 lacks and the reason a large borrowed
corpus beats a small perfect one.

## Decision

**Output quality is scored against docling's test-suite ground truth, with
markitdown scored on the same corpus as a control, by `bench/quality.py` behind
`bench/run-quality.sh`.**

Three constraints make the comparison mean something.

**docling is the target, not a contestant.** Its ground truth is its own frozen
output, regenerated by its `GEN_TEST_DATA` flag. It would score 1.00 by
construction, so it is not run at all. The reported head-to-head is anymd
against markitdown, both third parties to that reference.

**Scoring is style-insensitive.** `| --- |` against `| - |`, `#` against `##`,
`<!-- image -->` against nothing are conventions, not defects. Emphasis, link
targets, HTML comments and unicode punctuation are normalized away before
anything is compared, so the score cannot be gamed — or lost — by adopting
docling's formatting habits.

**Content and reading order are scored separately, and the pair is the
finding.** Content is token F1, order-insensitive. Order is token similarity,
order-sensitive. A two-column PDF read straight down the page retains every
token and scrambles their sequence, which no single similarity number
distinguishes from a converter that merely dropped a paragraph. Reported as a
pair, the gap isolates a reading-order defect from a content-loss defect. It
found the bug it was designed to find on the first run:
`table_mislabeled_as_picture.pdf` scores content 0.97 and order 0.49.

Explicit refusals — nonzero exit — are counted in their own column and withheld
from the averages. `bench/README.md` already argues that anymd's `ErrNoTextLayer`
on a scanned PDF is better than markitdown's silent exit-0 empty string;
averaging that refusal in as 0.00 would have the benchmark punish the behaviour
the project recommends. Exit-0-with-empty-output is *not* withheld, because that
is the silent failure, and it scores 0 like any other miss.

## Consequences

The first run says anymd loses, over 130 documents:

| | anymd | markitdown |
|---|---:|---:|
| content | 0.88 | **0.91** |
| order | 0.86 | **0.88** |
| tables | 0.75 | **0.85** |
| headings | **0.84** | 0.82 |

It wins the spreadsheet formats decisively (xlsx content **0.87** against 0.68)
and csv outright; it loses docx, html tables, and pdf. Publishing a number we
lose is the point of having it — the repository has been shipping speed tables
it wins for two releases while the fidelity question went unasked.

Four defects it localised immediately, none of which any existing test caught:

- `drawingml.docx` emits **13 bytes**; DrawingML canvas text and embedded chart
  data are dropped entirely.
- `textbox.docx` scores content **0.13**; Word text boxes (`w:txbxContent`) are
  not extracted. This and the row above are documents that convert to almost
  nothing *at exit 0* — the failure mode `bench/README.md` criticises markitdown
  for, in our own converter.
- Three PDFs show a content/order gap of 0.24–0.48. One bug: `pdfPageText` in
  `conv_pdf.go` orders glyphs `Y` descending then `X` ascending, interleaving the
  columns of a two-column page.
- `xlsx_07_gap_tolerance_.xlsx` scores tables **0.11**; one table is dumped per
  sheet with no splitting of separate logical tables on blank-row gaps.

It also retroactively substantiates 0002. Run either side of the vendored
parser, the scores are identical to two decimal places across all 130 documents
— the first evidence for that ADR's byte-identical claim that is not the seven
files it checked against themselves.

What this costs:

- **Agreement with docling is now the definition of quality.** Where docling is
  wrong, matching it scores well, and the benchmark cannot say so. Two corpus
  filenames — `table_misidentified_as_form`, `table_mislabeled_as_picture` — are
  docling's own record of getting a page wrong, and we are scored against those
  pages. A hand-curated corpus is the eventual answer; this is the one that
  could exist today.
- **The corpus lives outside the repository.** `run-quality.sh` takes a path to
  a docling checkout, as `run.sh` already does for markitdown. It keeps a large
  binary corpus and its MIT licensing out of the tree, at the cost of a
  benchmark that cannot run in CI unattended.
- **It cannot gate a release.** There is no threshold, only a number and a
  ranked list of the worst files. Turning it into a regression gate needs
  committed baselines, and baselines committed before the four defects above are
  fixed would enshrine them.
- **Coverage is partial.** docling ships no pairs for rss, msg, zip, ipynb, or
  images, so five of anymd's formats remain unmeasured.
