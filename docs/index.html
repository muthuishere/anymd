anymd

Any document to Markdown, in pure Go. A Go-native alternative to Microsoft's markitdown: no cgo, no Python, no native library to ship — one static binary that cross-compiles anywhere Go does, and the same code as an importable library.

API reference · Source · Benchmarks

Install

# CLI
go install github.com/muthuishere/anymd/cmd/anymd@latest

# or, without Go
curl -sSfL https://raw.githubusercontent.com/muthuishere/anymd/main/install.sh | sh

# library
go get github.com/muthuishere/anymd

Quickstart

The CLI writes Markdown to stdout and diagnostics to stderr, so it composes:

anymd report.docx > report.md        # one file to stdout
anymd -r docs/ -d build/md -q         # batch a tree, deterministic order
curl -s https://example.com/d.csv | anymd -t csv   # stdin, with a hint
anymd --llm scan.pdf                  # opt in: read a page with no text layer

The library is the same engine, without shelling out:

res, err := anymd.ConvertFile("report.docx")
if err != nil {
    log.Fatal(err)
}
fmt.Println(res.Title)     // when the format carries one
fmt.Println(res.Markdown)  // the GFM body

Why this one

One static binary

Builds with CGO_ENABLED=0 and cross-compiles anywhere Go does. Nothing to apt install, no poppler, no LibreOffice subprocess.

Library first

The CLI is a thin shell over the public API. Embed the converter in a Go service instead of running a Python process per file.

Built for hostile input

Converters never panic; container recursion is bounded by --max-depth; no subprocess, no shell, and no network at convert time unless you ask for it.

Honest failures

A scanned PDF returns a named ErrNoTextLayer, not an empty string at exit 0, so a pipeline can route it to OCR.

Deterministic output

Every converter emits through one set of GFM writers, so a table from a spreadsheet and a table from a Word document are byte-identical. Batch output is emitted in input order.

Scriptable

Exit 0 converted, 1 a document failed, 2 you called it wrong — so CI can tell the two apart.

Coverage is a number that is easy to report dishonestly. Counting files that produce substantive output (over 200 bytes), it is 19/31 for both tools — dead even. Where anymd refuses a file, markitdown often returns an empty string and exit 0.

Quality

Speed is the easy half. Fidelity is measured against docling's test corpus — 130 documents shipped as (source, expected markdown) pairs — scoring anymd v0.1.0 and markitdown 0.1.5 as third parties to the same ground truth. Scoring is style-insensitive; explicit refusals are withheld from the averages, but exit-0-with-empty-output is not.

aggregate, 130 documentscontentordertablesheadingslists

anymd leads every aggregate metric. The spreadsheet lead is the widest: xlsx content 0.98 against 0.68, xlsx tables 0.99 against 0.60. It still trails on odf (which routes through the PDF converter), on PDF content, and on PDF tables and headings, where anymd emits almost none — a missing feature, and the largest remaining gap on this benchmark.

What the default build does not do

No OCR, no audio transcription, no image captioning, and no network access of any kind while a document is being converted. None of that is missing — each one is opt-in behind --llm, off until you pass the flag, because turning it on costs money, sends document content to a third party, and makes the output non-deterministic.

anymd --llm deck.pptx                      # caption every figure
anymd --llm scan.pdf                       # read a page with no text layer
anymd --llm --llm-transcribe interview.m4a # transcribe audio

Captioning is one model call per distinct image — a logo repeated across 60 slides is captioned once — with per-document ceilings and a 4 KiB floor that skips furniture. A captioning failure degrades to the previous output rather than failing the document. Point --llm-base-url at a local Ollama or vLLM and nothing leaves the box. See LLM features for the config file, the precedence rules and the cost model.
