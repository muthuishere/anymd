Feed it a file, get clean GitHub-flavored Markdown — for an LLM context window, a diff,
or a docs pipeline. `anymd` is a Go-native alternative to Microsoft's
[markitdown](https://github.com/microsoft/markitdown), with a different set of trade-offs:

- **No cgo.** `CGO_ENABLED=0` builds. Nothing to link, nothing to `apt install`.
- **No Python.** No interpreter, no virtualenv, no wheels that need a C compiler.
- **No native library to ship.** No poppler, no libmagic, no LibreOffice subprocess.
- **Library first.** The CLI is a thin shell over the same public API you import.
- **Cross-compiles everywhere Go does.** `GOOS=windows GOARCH=arm64 go build` and you're done.

```console frame="terminal" title="zsh"
$ anymd report.docx > report.md
$ head -4 report.md
# Q3 Report

| Region | Revenue | Δ QoQ |
| --- | --- | --- |
```

And the same conversion as a library — the CLI is a thin shell over exactly this:

```go
package main

import (
	"fmt"
	"log"

	"github.com/muthuishere/anymd"
)

func main() {
	res, err := anymd.ConvertFile("report.docx")
	if err != nil {
		log.Fatal(err)
	}
	fmt.Println(res.Title)    // "Q3 Report", when the format carries one
	fmt.Println(res.Markdown) // the GFM body
}
```

### Speed

In-process — mean of 10 runs after a warm-up. This excludes interpreter startup, so it is
the honest number for a long-running service.

| file | anymd | markitdown | speedup |
|---|---:|---:|---:|
| test.docx | 0.59 ms | 17.86 ms | **30×** |
| test.xlsx | 0.64 ms | 7.35 ms | **11×** |
| test.pdf | 3.44 ms | 74.47 ms | **22×** |
| test_wikipedia.html (385K) | 11.55 ms | 104.15 ms | **9.0×** |
| Peak RSS (test_wikipedia.html) | **27 MB** | 160 MB | |
| Install footprint | **17 MB** (one binary) | 318 MB (venv + deps) | |

markitdown also pays **309 ms** of Python import and init on *every* invocation — real for a
shell pipeline, irrelevant to a long-running service, which is why both tables live on the
[benchmarks page](/anymd/benchmarks/).

### Quality

130 documents from [docling](https://github.com/docling-project/docling)'s test suite, scored
style-insensitively against its (source, expected markdown) pairs. docling is the target, not a
contestant — it would score 1.00 against its own output by construction, so it is not run.
This is the aggregate row; anymd leads every metric.

| metric | anymd | markitdown | what it catches |
|---|---:|---:|---|
| content | **0.92** | 0.91 | token F1, order-insensitive — dropped and invented content |
| order | **0.91** | 0.88 | token F1, order-**sensitive** — scrambled reading order |
| tables | **0.87** | 0.85 | each ground-truth table matched to its best candidate, scored on cell content |
| headings | **0.84** | 0.82 | fraction of ground-truth headings that survive |
| lists | **0.83** | 0.82 | fraction of ground-truth list items that survive |

The spreadsheet lead is the decisive one — xlsx content **0.98 against 0.68**, tables
**0.99 against 0.60**. anymd still trails on `odf` (which routes through the PDF converter), on
PDF content, and on PDF tables and headings, where it emits almost none. That is the largest
remaining gap, and the [benchmarks page](/anymd/benchmarks/) names it.

<div class="am-note">
	**Nothing leaves the box unless you ask.** Conversion makes no network calls at all by
	default. `--llm` is opt-in, per invocation, and there is no environment variable that turns
	it on globally: it adds vision-model captions for images, reads scanned PDFs that would
	otherwise return `ErrNoTextLayer`, and — behind the separate `--llm-transcribe` flag —
	transcribes audio. See [LLM features](/anymd/llm/).
</div>
